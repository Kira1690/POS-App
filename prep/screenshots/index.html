Table Management Bidirectional Sync
Tables created on web appear in mobile floor plan (Web → Mobile). Tables created on mobile appear on the web Tables page (Mobile → Web).
✅ PASS
🖥 Web — Tables Page (source of truth) #T-6891 (mobile-created) · #WEB-TABLE-01 (web-created) — both visible
📱 Mobile — Settings › Table Management › Main Floor Updated Total Tables: 3 · 20 seats — WEB-TABLE-01 pulled from server
Web → Mobile: Table WEB-TABLE-01 (8 seats) created via web dashboard → stored in Core Service DB. POS-App SyncEngine fires PullSyncService.pullTablesAndAreas() every 30 s → writes table to SQLite → emits TABLE_SYNC_COMPLETE event → TableProvider subscriber calls refreshTables() → TableContext updated. Mobile floor plan "Main Floor Updated" now shows Total Tables: 3, Total Capacity: 20 seats (was 2 tables / 12 seats before fix).

Mobile → Web: Table T-6891 (4 seats) created on mobile POS → synced to Core Service via push sync. Web Tables page shows #T-6891 · 4 seats · Available alongside existing T1/T2/T3 and WEB-TABLE-01.

Root cause fixed: Core Service GET /api/tables returned section as a Prisma joined object {id, name, ...} instead of a string. FloorPlanSettings.derivedTablePositions comparison f.name === table.section failed → tables assigned to wrong floor. Fix: TableApiClient.getTables() now normalises section to string client-side. Combined with mount-time refreshTables() and reactive TABLE_SYNC_COMPLETE event subscription.
