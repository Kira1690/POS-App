Bug Fix: Occupied Table UX
Bug discovered during QA_06 testing, root-caused, and resolved with an improved contextual UI
Bug: Occupied Tables Selectable in New Order Modal

When opening the New Order table selection modal, tables that were already Occupied (with an active in-progress order) could still be tapped by staff. This triggered a native Alert.alert() system dialog with generic text, breaking the flow and confusing staff during service.

Expected behavior: occupied tables should be visually distinct and tapping them should surface contextual options rather than a generic system alert.

Root Causes
Root Cause 1 — Implicit Boolean Prop
The allowOccupied prop on the table selection component was written without an explicit value: <TableSelectionModal allowOccupied /> In React, a JSX attribute present without a value defaults to true. This meant all occupied table blocks were treated as selectable, bypassing the intended lock guard.
Root Cause 2 — Occupancy Downgrade in State Derivation
The derived state function tablesWithRealOccupancy() checked for a matching active order in local in-memory state only. When the app launched fresh and local orders were not yet hydrated from storage, this function incorrectly downgraded real OCCUPIED statuses (sourced from the server) to AVAILABLE, hiding the occupied state from the selection UI entirely.
Fix: ExistingOrderModal Component + Visual Occupied State

A new ExistingOrderModal component replaces the generic Alert.alert() call. When staff tap an occupied table the modal presents three contextual actions:

  • Update Order — opens the existing order to add or remove items
  • Shift Table — moves the existing order to a different available table
  • Cancel & New Order — voids the existing order and starts a fresh one

Occupied tables in the selection grid now render with a red background tint and an "Occupied" label overlay, providing immediate visual feedback before any tap interaction.

The tablesWithRealOccupancy() function was updated to merge server-side table status with local order state, using the server status as the authoritative source when local orders are not yet hydrated from AsyncStorage.

Visual Evidence
QA_06_table1_selected Table 1 selected in New Order modal. Occupied tables now display red tint + "Occupied" label. Tapping an occupied table triggers ExistingOrderModal instead of a system alert.
QA_17_tables_occupied Floor plan after QA_06–12: T1 and Patio T1 correctly shown as Occupied (red tint). All other tables remain Available (green). Status accurately reflects server-sourced occupancy.
